# Local k3d deployment (`k8s-local/`)

A self-contained copy of the Kubernetes manifests that runs on a local **k3d**
cluster, for testing the 3/3/3 + MongoDB replica-set setup before deploying to AKS.

## How it differs from `k8s/` (the Argo CD / AKS manifests)

| Concern | `k8s/` (AKS) | `k8s-local/` |
| --- | --- | --- |
| Secrets | SealedSecrets (encrypted for the AKS controller) | plain `Secret`s generated by `gen-secrets.sh` (gitignored) |
| TLS / certs | cert-manager `ClusterIssuer` + TLS ingress to a public host | none — host-less plain-HTTP ingress |
| Images | `frikzy/library-api-*` from Docker Hub (CI-built) | `library-api-*:local`, built locally and imported into k3d |
| Delivery | Argo CD GitOps | manual `kubectl apply -k` |

Everything else (3 backend / 3 frontend replicas, the 3-member `rs0` MongoDB
replica set + keyfile + init job) is identical, which is the point — it mirrors prod.

## Argo CD must not manage the local namespace

If a local Argo CD `Application` syncs `path: k8s` from the GitHub repo with
`selfHeal: true`, it will continuously revert these manual applies back to the
AKS-flavored `k8s/` manifests (which don't work locally). Pause it first:

```bash
kubectl patch application library-api -n argocd --type=merge \
  -p '{"spec":{"syncPolicy":{"automated":null}}}'
```

(Re-enable later with `automated:{"prune":true,"selfHeal":true}` — but while it
points at `k8s`, leave it paused for local work.)

## Bring it up

```bash
# 0. Cluster running, kubectl context = k3d
k3d cluster start mycluster
kubectl config use-context k3d-mycluster

# 1. Build the images locally and import them into the cluster
docker build -t library-api-backend:local  -f Dockerfile .
docker build -t library-api-frontend:local -f frontend/Dockerfile frontend
k3d image import library-api-backend:local library-api-frontend:local -c mycluster

# 2. Generate the local (gitignored) plain secrets
./k8s-local/gen-secrets.sh

# 3. Deploy
kubectl apply -k k8s-local

# 4. Wait for the replica set, then verify it formed
kubectl rollout status statefulset/mongodb -n library-api --timeout=240s
kubectl logs job/mongodb-rs-init -n library-api
kubectl exec -n library-api mongodb-0 -- mongosh -u emc -p emc \
  --authenticationDatabase admin --quiet \
  --eval 'rs.status().members.map(m => m.name + " = " + m.stateStr)'
# expect: one PRIMARY + two SECONDARY

kubectl get pods -n library-api          # 3 mongodb, 3 backend, 3 frontend, init job Completed
```

The app is served at **http://localhost** (ingress-nginx, host-less ingress).
